# 双 DGX Spark 上的 V4.1 SSD KV 缓存

这份材料记录了一套已经在两台 DGX Spark 上跑通的方案，方便遇到相同问题的人直接复用。代码基于社区实现，补上了当前 V4.1 和 DSpark 所需的适配。

每台机器把自己的 KV 缓存写入本地 SSD，不需要为缓存搭共享文件系统。相同提示在服务重启后可以读回这些数据，减少重新处理长提示的时间。

每台配置是 128 GiB SSD 预算、512 MiB 内存中转，其中包含 128 MiB 分批读取缓冲区。服务就绪后，32K 提示的首字等待从 44.79 秒降到 1.12 秒；128K 从 179.00 秒降到 2.20 秒。两次恢复都正确找到了提示开头的标识符。这是单次测量，时间不包含模型启动。

包内有实际使用的 Python 实现、八个兼容文件、原始文件校验值、配置和测试脚本。英文 [SETUP.md](SETUP.md) 写了安装和重启复现步骤，[SOURCES.md](SOURCES.md) 列出了社区作者及来源。

它适用于我们验证过的 vLLM `0.1.dev20904+g179dd0fa9` 镜像。安装器会先核对版本和源文件，版本不同需要重新适配。内存和 GPU 数据一致性检查已通过；新版 vLLM、异常断电、单节点缓存丢失、长期满容量运行没有验证。编码测试也有失败记录，保留在 [验证结果](results/validation.json) 中。

这是一份可复现的经验分享。后来者可以从这里继续完善，也可以把适合的部分贡献回上游。
